## 1. 内容留存

诉求：`projects/1` 页按产品化标准优化样式、交互与动画。

改动（`smart-bid-doctor-web/src/views/ProjectDetailView.vue`）：

1. **概览指标条**：页面头部下方新增 4 张指标卡（已上传文件 / 解析中 / 清单条款 / 检查报告），数据全部复用已有列表接口，不新增请求；
   解析中时图标呼吸、徽标高亮（`@keyframes pulse-dot`），卡片 hover 上浮 2px + 阴影加深。
2. **流程引导动态化**：原先静态三步说明改为由真实数据推导：①双文件齐备 → ②双文件解析 `done` → ③已有报告；
   已完成步骤徽标打勾并点亮连接线，当前步用强调色实心徽标 + `step-pulse` 呼吸，避免「说的是流程但不是我的进度」。
3. **操作门禁前置**：生成清单 / 发起对照按钮按后端前置校验同口径禁用
   （`check.py`：招标文件 `done|need_review` 可生成清单；`compare_svc`：双文件均 `done` 才可对照），
   按钮下方新增 `.action-hint` 说明下一步缺什么，避免点了才收到 400。
4. **首屏骨架**：项目/文件/清单/报告并发拉取期间显示 `el-skeleton`（头部 + 4 格指标占位 + 内容块），不再先闪空态。
5. **任务进度细节**：状态点按状态着色（进行中呼吸、成功/失败/待复核定色），进度条补百分比文本并隐藏内置文字。
6. **报告表格交互**：整行可点（`cursor: pointer` + `@row-click`），类型标签按 checklist/comparison 分色，按钮点击 `@click.stop` 避免重复触发。

动画全部复用全站令牌与既有 keyframes，`prefers-reduced-motion` 下由 global.less 统一降级。

样式优化（用户截图反馈后）：
1. `UploadSlot.vue`：上传按钮改为固定宽度、`align-self:center`、未选文件时用中性 `default` 按钮
   （原禁用的 `primary` 在暗色下是偏亮浅底，抢视觉焦点）；选中文件后转 `primary` 并加 `@shadow-accent-sm`；
   选区补 `min-height:62px`、内边距收紧到 12/14px，右侧文案由「选择」改为「选择/更换」，选中后显示文件大小（`formatBytes`）。
2. `ProjectDetailView.vue`：`.upload-row` 由 `flex + min-width:280px` 改为 `grid repeat(2, minmax(0,1fr))`，
   两槽严格等宽，`<@bp-md` 回落单列；`.upload-slot` 去掉 `flex:1/min-width`，改 `min-width:0` 防长文件名撑破列。

一步上传（用户反馈「已上传为什么还有上传按钮、布局拥挤」后）：
- 移除选区右侧独立的「上传」按钮，改为**选中文件即自动上传**（`@change → onPick → onUpload`）；
- 上传中选区禁用（`cursor:progress`）、图标换成旋转 spinner（`zone-spin`），右侧实时显示百分比，
  第二行显示「文件大小 · 上传中 xx%」，下方细进度条（`stroke-width:4`、不显示内置文本）只做视觉进度；
- 尺寸超限直接提示并复位选择（`resetPicker`），不再出现「选了文件但传不上去」的空等状态；
- 布局回到单选区占满整列，去掉按钮占位后两列明显宽松（1024px 下每槽 327px）。
