# AI 工作留存（docs/records/）

本目录留存所有实质 AI 产出与验证证据，随仓库提交推送，供追溯、复盘与工程范式反哺使用。规则原文登记在根目录 `AGENTS.md` §AI 工作留存；本约定 2026-10-28 与用户对齐建立，对齐过程见 [2026-10-28-AI工作留存机制.md](./2026-10-28-AI工作留存机制.md)。

## 什么要记

- **修改任务**（L1 及以上）：AI 返回的方案与结论、实际改动（文件级）、SQL、测试证据。
- **问答 / 分析 / 评估 / 设计讨论**：AI 返回的实质内容（结论、方案、要点）。
- 纯寒暄、进行中的讨论不记；收尾后的实质结论照记（含 L0 只读问答）。

## 什么不入库

设计类文档与预测分析前置资料（`*.docx` / `*.doc` / `*.pptx` 等二进制）：沿用根 `.gitignore` 全局排除，不随开源库发布。

## 怎么记

- 一文一记，命名 `YYYY-MM-DD-主题.md`，模板见 [_TEMPLATE.md](./_TEMPLATE.md)。
- 三节固定结构，无对应内容的节写「无」，不删节：
  1. **内容留存** — AI 返回的实质内容与本次实际改动；
  2. **SQL 留存** — 对任何环境执行过的 DB 操作原文；SQL 较长时另存同名 `.sql`（如 `2026-10-28-主题.sql`）并在 md 内链接；alembic 迁移只记 revision id 与用途，不重复粘贴全文；
  3. **测试留存** — 验证表格（验证项 / 命令 / 退出码 / 结果摘要 / 证据位置）；未跑的写明原因（如本机无 DB，test-int 仅 CI 可跑）。
- 可选第四节「未验证项与风险」承接交付说明的对应项。
- 记录在任务收尾时写入，引用对应 commit hash，未提交时标注「未提交」，可随下一次任务一并提交。
- 本目录是分级 L0「不改仓库」的唯一例外：留存只新增本目录文件，不触碰任何业务内容。
