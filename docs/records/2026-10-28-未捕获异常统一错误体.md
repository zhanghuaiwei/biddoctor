# 2026-10-28 未捕获异常统一错误体（500 回具体信息）

- 类别：任务
- 级别：L3（统一错误体契约扩展：新增错误码 `INTERNAL_ERROR` + 兜底 handler）
- 关联：未提交

## 1. 内容留存

问题：未捕获异常走 Starlette `ServerErrorMiddleware` 默认分支，返回纯文本 `Internal Server Error`，
前端 `client.ts` 解析不到 `{"error":{code,message}}`，只能显示兜底文案（如登录 500 时完全看不到原因）。

改动：

1. `app/core/errors.py`：登记 `INTERNAL_ERROR: 500`（由 handler 直接产出，不经 `AppError`）。
2. `app/main.py`：新增 `@app_.exception_handler(Exception)` 兜底
   - 统一体恒为 `{"error":{"code":"INTERNAL_ERROR","message":...}}`，并补回 `X-Request-ID` 响应头
     （`ServerErrorMiddleware` 位于中间件栈最外层，拿不到 request_id 中间件写入的头）；
   - `logger.exception` 记录完整堆栈与 `request_id`，便于服务端追溯；
   - **分级**：dev 回 `异常类型: 描述`（截断 500 字，含 SQL 报错便于定位）；prod 只回
     `服务器内部错误，请稍后重试（request_id: xxx）`，避免泄露 SQL/文件路径/内部实现。
3. `tests/test_smoke.py`：新增两条用例——dev 回具体异常且带 request_id；prod 掩码内部细节。
4. `AGENTS.md`：错误码范式行补充兜底约定与 dev/prod 分级（反哺）。
5. 前端无需改动：`src/api/client.ts` 已有 `j?.error?.message` 解析，`notifyApiError` 直接展示。
